What you can use it for

A measuring tool for how much a device's sound gives away.

Test your own devices

Record 25 presses of each key on a laptop, train in minutes on a CPU, and get a score for how recognisable that device is from a phone or a call.

Compare hardware

Run the same test on different keyboards, mounts or microphones to see which gives the least away, and show the number.

Add a confidence gate

Act only on the presses the model is 80%+ sure of (98% right), and use its top three guesses (right key in 97.5%) to narrow the rest.

These are possible uses. None has been tried with a client.

Where it fits

Each model is tuned to the device it learned from.

How to read: in each pair the dark bar is the model tested on the device it learned from; the red bar is the same model on a different device. Train on the device you want to measure.

Phone and Zoom recordings are one MacBook Pro 16 (44.1 kHz phone, 32 kHz Zoom). The laptop pair uses two public sets from different MacBook Pros, rooms and microphones, same 22 kHz format. One run each for the cross-device tests. Click a bar for the run.

How we tested it

Data25 presses of each of 36 keys (a to z, 0 to 9), one person, one MacBook Pro, recorded by a phone and through Zoom. Two public laptop sets for the laptop test.
ModelEach press becomes a 64-band sound picture, read by a compact network mixing convolution and attention. CPU only, 150 epochs.
Discipline80% of presses to learn, 10% to choose when to stop, 10% kept back and scored once. Several random splits; every run listed.
LimitsOne person, one laptop, one room. A smaller model than the one published. The Listen tab replays held-out presses; it does not process anyone's audio.

Method follows Harrison, Toreini and Mehrnezhad, "A Practical Deep Learning-Based Acoustic Side Channel Attack on Keyboards" (arXiv 2308.01074). Recordings: Keystroke-Datasets and R-ASCA. Code and every run: GitHub.
